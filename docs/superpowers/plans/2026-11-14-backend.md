# Backend (Role B) Implementation Plan: Own Your Baseline API

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `api/` service (role B): pure health logic (baseline, drift, alerts, open-record views, brief pinning), SQLite text records, a simulated ground link with a sync log, and the HTTP endpoints A's web app calls.

**Architecture:** Hexagonal. `api/domain/` holds pure functions with no I/O and no clock (time is passed in). `api/store/` (SQLite) and `api/metrics/` (adapter over C's `pipeline/queries/` and ingest helper) are ports with adapters. `api/routes/` wires them. A `FakeMetrics` adapter lets B build and test everything before C's VictoriaMetrics work lands.

**Tech stack:** Python 3.12+ (local is 3.14; Docker image pins 3.12), FastAPI, Pydantic v2, uvicorn, stdlib `sqlite3` (no ORM), pytest + httpx `TestClient`, ruff, `uv` for deps.

**Spec:** `docs/TEAM.md` (section B), `docs/REQUIREMENTS.md` (M5, D1, D3–D7, U3, U4, U9–U11, S3), `docs/USER-FLOW.md`, `CLAUDE.md` rules.

## Context

No application code exists yet and `docs/DECISIONS.md` is not written (`docs/HANDOFF.md`). The user is role B only. B's work blocks A (needs `api/openapi.json`) and depends on C (query functions C5, ingest helper C2). This plan sequences B so the contract lands first, then pure logic with tests, then storage and endpoints, using a fake metrics adapter until C's code is merged.

## Global Constraints

- Decision support, not diagnosis: every alert/readout string uses "possible", "worth checking", "compare with your baseline". Never "you have", "diagnosis". Field `disclaimer: "Decision support, not a diagnosis."` on every view and readout.
- Open record: astronaut and ground views built by **one function** from one record. No ground-only fields. Every note, flag, measurement request, reply visible to the astronaut after delivery.
- Every sync listed in the sync log.
- `api/domain/` does no I/O and never calls `datetime.now()`; `now` is a parameter.
- Every threshold: source comment, or `# Demo parameter` in code and `"demo_parameter": true` in API output.
- Every series point carries `source: "sim" | "nasa"`; views pass it through so A can label "Simulated".
- No internet calls, no auth, no accounts. Role is a UI switch.
- B never writes raw MetricsQL; calls C's functions in `pipeline/queries/`.
- Earth/OSD-569 ranges are reference only, never trigger an alert.
- Branches `b/<topic>` off `main`, PR + squash, `make check` green. Commit only when the user asks. No Claude co-author lines (HANDOFF gotcha).

## Review Focus

1. **Missing days / gaps** in a series (sensor off, skipped check-in): baseline uses available days, counts calibration by days with data, never crashes on empty list. Test in Task 1.
2. **VictoriaMetrics unreachable**: views still return SQLite content with indicators `"unavailable"`; endpoint never 500s. Test in Task 5.

5. **Sync with nothing queued**: still logged with zero counts, `last_sync_at` advances. Test in Task 8.

### Task 5: Metrics port, check-in endpoint, open-record views (B5, B6, D2, D3, D4, U1) — ~3 h

Branch `b/checkin-views`. **Files:** `api/metrics/port.py`, `api/metrics/fake.py`, `api/metrics/pipeline_adapter.py` (stub until Task 10), `api/domain/views.py`, `api/services/record.py`, `api/clock.py`, `api/routes/astronaut.py`, `api/routes/ground.py`, `api/routes/reference.py`, tests in `api/tests/routes/` and `api/tests/domain/test_views.py`.

**Produces:**
- `class MetricsPort(Protocol)`: `daily(crew_id, key, start, end) -> list[DailyPoint]`; `series(crew_id, key, days) -> list[Point]`; `write(crew_id, values: dict[IndicatorKey, float], at: datetime) -> None`. Raises `MetricsUnavailable`.
- `FakeMetrics`: in-memory, seeded with a 14-day story like C3 (baseline, CO2 rise day 9, headaches day 10, recovery day 12), `source="sim"`. Selected by env `METRICS_BACKEND=fake|vm` (default `fake`).
- `Point(at: datetime, value: float, source: str)`; `Record(crew_id, indicators_series: dict[IndicatorKey, list[DailyPoint]], checkins, alerts, briefs, replies, notes, readiness, last_sync_at)` — plain dataclass loaded by `services/record.load_record(repo, metrics, crew_id, now)`.
- `build_view(record: Record, side: Literal["station","ground"], now) -> RecordView` — **the one function** for both roles. Visibility by origin:
  - Astronaut-origin items (series, check-ins, alerts, briefs) show on `ground` only if created at or before `last_sync_at`; on `station` always.
  - Ground-origin items (notes, flags, requests, replies) always show on `ground`; on `station` once `delivered_at` is set.
  - A's "What ground sees" calls `/ground/{id}/view`, so both screens get identical bytes.
- `services/record.evaluate(repo, metrics, crew_id, now) -> None`: loads points, runs `compute_baseline` → `detect_drift` / `detect_headache_pattern` → `build_alert`, dedupes against open alerts (same indicator + overlapping range = same alert), applies `select_daily`, persists, closes alerts where `should_close`. Runs after every check-in and on `POST /demo/reset`; GETs never evaluate.
- `Clock.now() -> datetime` FastAPI dependency (seeded demo time, see Task 0), overridden in tests.
